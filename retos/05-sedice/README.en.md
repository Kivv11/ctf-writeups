# Sedice

[Español](README.md) | [English](README.en.md)

**Challenge 5 · Web Hacking · Difficulty: Medium**

## Challenge

> The platform relies on signed tokens and role-based access controls to protect administrative functions, but something in the implementation appears dangerously fragile.
>
> A more thorough investigation has uncovered a forgotten configuration backup containing sensitive authentication secrets. With these credentials, it was possible to forge trusted identities and access areas of the platform reserved for administrators.
>
> Your objective is to analyze the authentication flow, exploit the vulnerability, and retrieve the protected flag hidden behind the administration interface.

[Link](https://challenges.hackrocks.com/sedice)

## Flag
```
jwt_4nd_l0c4l_st0r4g3_t4mp3r1ng_g0es_brr
```

## Solution using CyberChef and JWT.io

[CyberChef](https://gchq.github.io/CyberChef/) is used to decode the JWT with `JWT Decode` and calculate the `MD5` hash of the second token. The JWT is signed using [JWT.io](https://www.jwt.io/), under its **JWT Encoder** tab.

The first vulnerability was found in a publicly exposed configuration file.

To find it, [**FFUF**](https://github.com/ffuf/ffuf), a web directory and file enumeration tool, was used alongside the env-backups.txt wordlist, containing 78 paths related to `.env` files and backups.
```bash
.\ffuf.exe -u https://challenges.hackrocks.com/sedice/FUZZ -w .\env-backups.txt -mc all -fc 404 -rate 5 -t 2
```

The command parameters are:

- `-u https://challenges.hackrocks.com/sedice/FUZZ`: specifies the target URL. `FUZZ` is the placeholder replaced by each path from the wordlist.
- `-w .\env-backups.txt`: specifies the file containing the paths to be tested. The `.\` prefix indicates the current directory in Windows.
- `-mc all`: matches responses with any HTTP status code.
- `-fc 404`: excludes HTTP 404 responses (resource not found) from the results. Combined with `-mc all`, it allows other status codes to be observed.
- `-rate 5`: limits the request rate to 5 requests per second.
- `-t 2`: uses 2 concurrent threads. This concurrency limit, together with the request rate limit, controls the scanning load.

`.\ffuf.exe` executes the FFUF binary located in the current directory.

The scan found:
```yaml
backup/.env.bak    [Status: 200, Size: 54]
```

The starting point is the exposed configuration file at `/sedice/backup/.env.bak`:
```ini
SECRET_KEY=s3cr3t_jwt_k3y_ananta_ctf
SALT=xG9AmK2$$pL
```

The session uses a JWT and a second token called `ls_token`, whose identified derivation is:
```ini
ls_token = MD5(JWT completo + SALT)
```

The `+` sign indicates concatenating both strings without a separator. A **JWT** contains a header, a payload with user information, and a signature. **HS256** uses HMAC-SHA256 and a shared secret key to sign and verify the token.

### ls_token formula

The original `jwt` and `ls_token` were obtained from the same session before modifying the role. Using the `SALT` and `SECRET_KEY` from the exposed file, different combinations were tested, and each result was compared against the original second token using the script provided by GPT.

### Modify the role and sign the JWT

[JWT.io](https://www.jwt.io/) is used to sign the JWT. The rest of the procedure can still be performed using CyberChef.

1. Obtain the JWT from a regular session through DevTools, in the site's local storage (`localStorage`, key `jwt`).
2. Paste the token into CyberChef and apply `JWT Decode` to read its payload.
3. Copy the JSON payload and change `"role":"user"` to `"role":"admin"`, keeping `sub` and `username` unchanged. The `exp` field must contain a future Unix timestamp expressed in seconds.
4. Open JWT.io and select **JWT Encoder**. Choose the `HS256` algorithm and enter the modified payload in the corresponding editor.
5. Use the header `{"alg":"HS256","typ":"JWT"}` and enter `s3cr3t_jwt_k3y_ananta_ctf` in the **Secret** field.
6. Copy the signed JWT generated by JWT.io. This output is the administrative JWT used to calculate the new `ls_token`.
7. Return to CyberChef and, in a new *recipe*, paste the complete JWT just signed in JWT.io, immediately followed by the salt:
```
<JWT_ADMIN>xG9AmK2$$pL
```

Replace the placeholder with the actual token. Apply `MD5`: its 32-character hexadecimal output is the new `ls_token`.

### Request the flag

From the browser console, while on the challenge page, replace the two placeholders with the obtained values:
```javascript
fetch('/sedice/api/flag', {
  headers: {
    'Authorization': 'Bearer JWT_ADMIN',
    'X-LS-Token': 'LS_TOKEN'
  }
})
.then(response => response.json())
.then(console.log);
```

The recorded successful response was HTTP 200:
```json
{
  "flag": "jwt_4nd_l0c4l_st0r4g3_t4mp3r1ng_g0es_brr",
  "message": "Welcome, snow. You have root."
}
```
