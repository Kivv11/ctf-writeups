# Regional Clearance Portal

[Español](README.md) | [English](README.en.md)

**Challenge 3 · Web Hacking · Difficulty: Easy**

## Challenge

> You have access to the public clearance portal used by a company's local offices. Guest lookup works with regular credentials, but the admin clearance code is only provided to privileged accounts.
>
> Find a way to authenticate as admin without knowing the password.
>
> The login endpoint uses JSON, not an HTML form.

[Link](https://challenges.hackrocks.com/regional-clearance-portal/)

## Flag
```
flag{web_nosql_clearance}
```

## Solution

Upon accessing the portal, the API documentation and service status endpoints are displayed:
```yaml
Regional Clearance Portal

API documentation: /api/docs/
Health: /api/health
```

## API

An **API** is an interface that allows communication with an application through requests.

## Endpoint

An **endpoint** is a specific route within that interface; in this case, `POST /api/login` receives the login credentials.

## POST

**POST** is the HTTP method used to send data to the server.

The [API documentation](https://challenges.hackrocks.com/regional-clearance-portal/api/docs/) indicates that the request body uses `application/json` and that the `password` field accepts JSON objects, including a reference to *operator injection*.

## JSON

**JSON** is a data interchange format based on *key-value* pairs. A string is text enclosed in quotation marks, while an object groups pairs inside curly braces. For example, `"guest"` is a string, whereas `{"$ne":"assasd"}` is an object.



This hint suggests testing a **NoSQL operator injection**: inserting a query operator into a field that should be treated as data. NoSQL encompasses different database models; some, such as MongoDB, allow conditions to be expressed using objects.

The **`$ne`** operator means *not equal*. Instead of providing the correct password, a condition is inserted that matches a password different from a chosen value. [More about ](https://www.mongodb.com/docs/manual/reference/operator/query/ne/)[`$ne`](https://www.mongodb.com/docs/manual/reference/operator/query/ne/).

## Request through the API documentation

1. In the username field, enter `admin`.
2. In the password field, enter the object `{"$ne":"assasd"}`.
3. Click **Execute**.

The attempted condition can be interpreted as follows:
```
username = admin
AND
password not equal to assasd
```

`assasd` is an arbitrary value used in the test. The condition works if the stored value is different and the server interprets the object as an operator instead of rejecting it.

The command displayed by the interface itself is:
```rust
curl -X 'POST' \
  'https://challenges.hackrocks.com/regional-clearance-portal/api/login' \
  -H 'Content-Type: application/json' \
  -d '{
  "username": "admin",
  "password": {
    "$ne": "assasd"
  }
}'
```

## CURL

**curl** is a command-line tool used to make HTTP requests. The command generated by the page is preserved here.

The screenshot shows an **HTTP 200** response with the following content:
```json
{
  "success": true,
  "username": "admin",
  "clearance_code": "flag{web_nosql_clearance}"
}
```

The server accepts the request as `admin` and returns the clearance code without the admin password being provided.

## Conclusions

An object received in the password field must not be allowed to modify the authentication condition. Input types should be validated, and user-controlled operators must not be incorporated into database queries.
